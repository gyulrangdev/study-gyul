# 한국어 학습 노트북 만들기

영문 커리큘럼 한 단원을 **읽어도 되고 발표해도 되는** 한국어 주피터 노트북으로 옮긴다.

이 문서는 실제 작업에서 받은 피드백을 모은 것이다. 규칙마다 **왜 그런지**가 붙어 있다.
이유를 모르면 비슷한 실수를 다른 모양으로 반복하게 된다.

## 0. 시작 전 반드시 할 일

### 원문을 최신으로 맞춘다

로컬 클론이 있으면 **먼저 `git pull`** 한다.

> 실제로 겪은 일: 818 커밋 뒤처진 클론으로 세 단원을 만들었다.
> 다행히 바뀐 게 LaTeX 서식뿐이었지만, 확인 안 했으면 몰랐다.

웹 게시본과 로컬이 다를 수 있다. **원문 파일 전부**를 본다.

| 파일 | 왜 봐야 하나 |
| --- | --- |
| `docs/en.md` | 본문 |
| `code/*.py` | 구현. 의사코드만 있던 게 실제 코드로 채워지기도 한다 |
| `quiz.json` | 퀴즈. **이게 있는데 "원문엔 없다"고 쓰면 거짓말이 된다** |
| `outputs/*.md` | Ship It 산출물. 같은 이유 |

- 파이썬은 `/opt/homebrew/anaconda3/bin/python3` (bare `python3` 아님)
- 노트북 실행 시 `MLFLOW_DISABLE_AGENT_HINT=1`
- 생성기 스크립트는 scratchpad에 둔다. **지워질 수 있으니** 중요하면 백업

## 1. 글의 뼈대

### 노트북 전체 구조

```
① 제목 + 여는 문장
② 이 단원이 푸는 문제          ← 구체적인 상황에서 시작
③ 이걸 배우면 뭘 할 수 있나     ← 받게 될 요청 + 어느 절이 답하는지
④ 이 단원의 줄거리            ← 서술형. 절 목록은 <details>로 접는다
⑤ 0. 준비 (폰트 등)
⑥ 각 절 (아래 구조)
⑦ 정리 · Ship It · 용어 · 퀴즈
```

### 각 절의 구조

```
## N. 제목                      ← 숫자는 보통 숫자. 0️⃣ 같은 이모지 금지
<sub>📗 원문 "Section Title"</sub>   ← 출처는 작게 한 줄

앞 절에서 ~했습니다. 그런데 ~.   ← 다리는 '본문 첫 문단'. 인용 상자 금지

### 개념 설명

> 실험 N · 짧은 제목            ← 발표용 카드 (앞)
> 🎯 배울 것 — ...
> 🔬 하는 일 — ...

[코드 셀]

> 👀 주목할 곳 — ...            ← 발표용 카드 (뒤)
> ✅ 알게 된 사실 — ...
```

## 2. 발표용 4단 카드 — 가장 중요한 규칙

실험마다 코드 셀을 가운데 두고 앞뒤에 상자를 붙인다.
**이 네 상자와 출력만 띄우면 발표 한 꼭지가 되어야 한다.**

```markdown
> **실험 7** · 고립 숲의 원리
>
> **🎯 배울 것** — 이상치는 적고 다릅니다. 그래서 적은 질문으로 혼자 떼어낼 수 있습니다.
>
> **🔬 하는 일** — 무작위로 자르는 트리를 직접 만들고, 각 점이 혼자 남기까지 걸린 깊이를 셉니다.
```

```markdown
> **👀 주목할 곳** — 경로 길이 `정상 13.153` vs `이상 4.570`. 그리고 sklearn 과의 순위 상관 0.96.
>
> **✅ 알게 된 사실** — 이상치가 2.9배 빨리 고립됩니다. 점수 공식은 그 경로 길이를
> 데이터 크기로 정규화한 것뿐입니다.
```

### 각 칸에 뭘 쓰나

| 칸 | 쓸 것 | 쓰지 말 것 |
| --- | --- | --- |
| 🎯 배울 것 | **주장 한 줄.** 이 실험이 세우려는 명제 | "~를 알아봅니다" 같은 빈 말 |
| 🔬 하는 일 | 무엇을 어떻게 재는지 | 코드 설명 반복 |
| 👀 주목할 곳 | **어느 열·어느 숫자**인지 콕 집어서 | "출력을 보세요" |
| ✅ 알게 된 사실 | 그 숫자가 **왜** 그런지 | 주목할 곳의 반복 |

### 왜 이 구조인가

- 이전에는 안내를 **노트북 앞에 몰아** 뒀다. 정작 셀을 돌릴 때는 40셀 위에 있었다
- ①이 긴 서술에 묻혀 "이걸 왜 보는지" 모르는 채로 코드를 읽게 됐다
- ③과 ④가 한 덩어리라 "뭘 보라는 건지"와 "그래서 뭔데"가 안 갈렸다
- 발표할 때 보여 줄 단위가 없었다

## 3. 책처럼 이어 읽히게

### 절 사이를 끊지 않는다

❌ **나쁜 예** — 상자 두 개가 본문 앞을 막는다

```markdown
## 3. 라플라스 스무딩

> 📗 **원문** — "Laplace Smoothing"
>
> 🔗 **앞 절과 이어서** — 2절에서 +1을 왜 더했는지 아직 설명 안 했습니다.

### ⚠️ 문제
```

✅ **좋은 예** — 다리가 첫 문단이다

```markdown
## 3. 0을 막는 장치 — 라플라스 스무딩

<sub>📗 원문 "Laplace Smoothing"</sub>

앞 절 끝에서 숙제를 하나 남겼습니다. 분자에 더한 `+1`, 분모에 더한 `+3` 말이죠.
그게 라플라스 스무딩이고, 이 절이 그 이야기입니다.

가장 빠른 이해 방법은 **빼 보는 것**입니다. 안 더하면 무슨 일이 생길까요?

### 안 더하면 생기는 일
```

### 절 끝에는 '생각의 흐름'을 답니다

실험 카드는 **이 실험이 뭘 보여 줬나**다. 그것만으로는 절이 왜 여기 있는지 모른다.
절 끝에 한 상자를 더 달아 **층을 나눈다.**

```markdown
> **🧩 이 절의 결론**
>
> 이상치는 세 종류고, **이 단원에서 만들 도구는 전부 ①번만 잡습니다.**
> ②③번을 잡고 싶으면 도구가 아니라 **넣어 주는 숫자를 바꿔야** 합니다.
>
> **➡️ 다음**
>
> 3절부터 ①번용 도구를 하나씩 만듭니다.
> ②③번을 위한 숫자 만들기는 15단원이 맡습니다.
```

| 층 | 상자 | 답하는 질문 |
| --- | --- | --- |
| 실험 | 🎯🔬👀✅ | 이 실험이 뭘 보여 줬나 |
| 절 | 🧩➡️ | **이 절이 왜 여기 있고 어디로 가나** |

`➡️ 다음` 에는 **왜 다음 절로 가는지**를 쓴다. 목차 읽기가 아니다.

❌ "다음은 4절입니다"
✅ "방금 '이상치가 멀리 있으면' 이라는 조건이 붙었습니다. 4절에서 그 조건을 깨뜨려 봅니다"

여기서 **범위도 밝힌다.** 이 단원에서 안 다루는 건 어디서 다루는지 적어 준다.
안 그러면 "그래서 ②③번은?" 하고 막힌 채로 남는다.

### 용어를 쓰기 전에 짚는다

**설명 안 한 용어를 먼저 쓰면 그 자리에서 끊긴다.**

> 실제로 겪은 일: 2절이 스무딩을 쓰는데 설명은 3절에 있었다.
> 노트북이 스스로 *"2절에서 왜 더했는지 아직 설명 안 했습니다"* 라고 자백하고 있었다.

순서를 못 바꾸면 **미리 짚고 넘긴다.**

```markdown
식에 $+\alpha$ 가 두 군데 붙어 있는 게 보이실 겁니다.
지금은 **"0이 나오는 걸 막는 장치"** 정도로만 알아 두세요.
왜 필요한지는 **다음 절에서 제대로 다룹니다.**
여기서는 숫자를 따라가는 데만 집중하시면 됩니다.
```

그리고 다음 절이 **그걸 받는다.** "앞 절 끝에서 숙제를 하나 남겼습니다" 처럼.

### 목차 표 대신 줄거리

목차 표 + 불릿 흐름도는 **설명 안 된 용어가 먼저 등장하는** 통로가 된다.
서술형 줄거리로 쓰고, 용어 대신 **하는 일**로 설명한다.

❌ "3절: 스무딩이 필요합니다 / 4절: 언더플로를 막습니다"

✅ "첫 번째는 **처음 보는 단어**입니다. 훈련에 없던 단어가 나오면 그 확률이 0이 되는데,
전체가 곱셈이라 답도 통째로 0이 됩니다."

절 목록은 `<details>` 로 접어서 뒤에 둔다.

### "지금 어디쯤 와 있나"

여러 단원이 한 묶음이면 **전체에서의 위치**를 먼저 알려 준다. 이게 특히 반응이 좋았다.

```markdown
### 지금 어디쯤 와 있나

1단원부터 13단원까지는 **"어떤 모델이 더 좋은가"** 를 배웠습니다.
14단원부터는 질문이 바뀝니다.
**"지금까지 당연하게 쓰던 기본값이 통하지 않는 상황"** 을 하나씩 보게 됩니다.
```

## 4. "왜 배우나"는 받게 될 요청에서 시작

번역된 Learning Objectives 불릿은 **가장 번역투인 블록**이다. 버린다.

❌ 나쁜 예
```markdown
## 🎯 이 단원에서 배우는 것
1. Z-score, IQR, Isolation Forest 를 밑바닥부터 만듭니다.
2. 점·맥락·집단 이상치를 구분하고, 각각에 맞는 방법을 고릅니다.
```

✅ 좋은 예
```markdown
## 이걸 배우면 뭘 할 수 있나

> **"로그에서 이상한 거 좀 찾아봐 주세요."**

이런 요청이 막막한 이유는 정답지가 없어서입니다.

이 단원을 지나면 그 한 줄짜리 요청을 **답할 수 있는 질문 넷**으로 쪼갤 수 있게 됩니다.

| 질문 | 어디서 | 이 단원의 답 |
| --- | --- | --- |
| 뭘 찾는 건가요? | 1절 | 값이 튀는 건지, 때가 안 맞는 건지부터 정합니다 |
| 잘 잡는지 어떻게 재죠? | 10절 | 정확도와 AUROC 는 거짓말합니다 |
```

핵심은 **실제로 듣는 말**로 시작하는 것이다.
"정확도 99% 나왔습니다", "특징을 더 넣었는데 성능이 떨어져요" 같은.

## 5. 비유는 지어내지 않는다

**원문이 쓰는 예시만 쓴다.**

> 실제로 겪은 일: 비유를 10개 지어 넣었다가 전부 걷어냈다.
> 판사 100명의 거부권, 스무고개, 서울과 시골의 집, 키로 성별 맞히기,
> 고양이와 강아지, 계단 오르며 흔들리는 사람, 친구의 친구 친밀도…
> **비유가 많아지면 비유끼리 경쟁해서 오히려 이해를 막는다.**

원문은 보통 비유가 아니라 **도메인 예시**를 쓴다.
"뉴욕 오후 2시 결제가 2시 5분 도쿄에서", "겨울의 90°F", "로그인 실패 5번과 연속 50번".
그걸 그대로 살린다.

비유 없이 설명이 안 될 것 같으면 **직접 말한다.**

| 지어낸 비유 | 직접 말하기 |
| --- | --- |
| 판사 100명이 거부권을 행사하면 | "전체가 곱셈이라 0을 한 번 곱하면 결과가 0입니다" |
| 스무고개로 사람 찾기 | "몇 번 만에 혼자 남았나. 세는 건 그것뿐입니다" |
| 과장하는 친구의 말 번역 | "순위는 그대로 두고 값만 고칩니다" |

예시를 들더라도 **단원의 도메인 안에서** 든다.
스팸 단원이면 끝까지 스팸으로. 중간에 폐렴이 나오면 거기서 흐름이 끊긴다.

가능하면 **노트북이 실제로 쓰는 데이터**를 가리킨다.
("아래 코드에서는 Iris 꽃잎 길이와 Wine 화학 성분으로 확인합니다")

## 6. 모든 주장을 측정한다

**원문이 그렇다고 해서 그런 게 아니다. 돌려 보고 쓴다.**

### 절차

1. 생성기 스크립트로 `.ipynb` 를 만든다
2. **셀마다 `exec()` 로 드라이런**한다
3. **찍힌 숫자를 하나씩 읽고 주변 서술과 대조한다**
4. 안 맞으면 고친다. 보통 한 단원에 10여 곳 나온다
5. `jupyter nbconvert --execute` 로 실행

### 원문과 다르면 정직하게 적는다

지우거나 얼버무리지 않는다. ⚠️ 를 붙이고 **측정값과 함께** 쓴다.

```markdown
| 📗 원문의 주장 | 측정 결과 | 절 |
| --- | --- | --- |
| "트리는 추세를 다루고 선형은 정상성이 필요하다" | **반대입니다.** 트리는 외삽을 못 해 차분이 필수고, Ridge는 차분 없이도 됩니다 | 9 |
```

그리고 **왜 다른지**까지 파고든다.
"트리 예측은 잎의 평균이라 훈련 최댓값(82.30)을 못 넘는데 테스트 실제값은 92.99까지 갑니다."

확인된 것도 따로 표로 적는다. 반증만 모아 두면 원문이 부실해 보인다.

### 예제 데이터의 함정을 의심한다

> 실제로 겪은 일: 원문 예제가 잡음 열에만 `*0.5` 를 곱해 둬서,
> **정답을 보지도 않는 분산 필터가 1등**으로 나왔다.
> 표준화하니 바로 무너졌다.

"이 방법이 1등일 리가 없는데?" 싶으면 데이터를 들여다본다.

## 7. 말투

### 기본

- **강의체 존댓말.** 질문을 던지고, 답하고, 다음으로 넘어간다
- 한 문단은 한 가지만
- 문장 길이를 섞는다. 짧은 문장도 쓴다

### 아는 사람 기준으로 쓰지 않는다

원문은 **이미 다 아는 사람을 위해** 쓰여 있다. 그대로 옮기면 안 읽힌다.

- 용어가 나오면 **그 자리에서** 한 번 풀어 준다. 뒤로 미루지 않는다
- 수식은 쓰되 **말로 한 번 더** 말한다
  ("$I(X;Y)$ 는 X를 알 때 Y의 불확실성이 얼마나 줄어드는지입니다")
- "당연히", "잘 알려진 대로" 같은 말을 쓰지 않는다. 당연하지 않다

### 양을 늘리지 않는다

원문보다 길어지는 건 **설명이 늘어서**여야지 **말이 늘어서**면 안 된다.

| 늘려도 되는 것 | 늘리면 안 되는 것 |
| --- | --- |

## 8. 출처 표시

사용자가 **원문과 내 추가분을 구분**할 수 있어야 한다.

| 표시 | 뜻 |
| --- | --- |
| 📗 | 원문에 있는 내용 |
| ✨ | 원문에 없고 내가 넣은 예시·실험 |
| ⚠️ | 원문 주장이 측정과 달랐던 곳 |

머리말에 **한 줄로** 적는다. 따로 절을 만들면 본문 시작을 막는다.

```markdown
- 표시 규칙: 📗 는 원문에 있는 내용, ✨ 는 제가 넣은 예시·실험, ⚠️ 는 원문과 측정이 달랐던 곳입니다.
```

절 단위 출처는 제목 밑에 `<sub>📗 원문 "Section Title"</sub>` 한 줄.

## 10. 정규식으로 본문 일괄 수정할 때

**스크립트로 마크다운을 건드릴 때 실제로 터진 사고들이다.**

| 사고 | 원인 | 막는 법 |
| --- | --- | --- |
| `오차**2 … 오차**2` → `오차2` | 지수 연산자 둘을 굵게 한 쌍으로 오인 | 토크나이저로 **문자열 토큰만** 고르고, 문자열 내용을 비운 AST를 비교해 검증 |
| `**A**와 **B**` → `**A**와**B**` | 닫는 `**` + 여는 `**` 를 한 쌍으로 보고 사이 공백을 먹음 | 여는 `**` 앞은 공백이어야 한다는 전제. 줄 단위 패리티로 판정 |
| `⚠️` → `⚠` | 이모지 문자열을 **코드포인트로 순회**해 U+FE0F 가 따로 떨어짐 | `장식 = ["🔑", "🧸"]` 처럼 **리스트**로 둔다 |

공통 교훈 세 가지.

1. **위험 사례로 먼저 시험한다.** 바꾸기 전에 10여 개 입력으로 기대 동작을 확인
2. **기계적으로 검증한다.** "문자열만 바뀌었다"를 AST 비교로 증명
3. **마크다운만 바꿨으면 재실행이 필요 없다.** 코드를 건드렸을 때만 다시 돌린다
